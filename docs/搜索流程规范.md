# 搜索流程规范（SimpleMCPServer · 2026-10-17 确立）

> 用途：所有需联网检索/事实核验/资料搜集的任务（人物事迹、史料复核、数据查证）统一走此流程。
> 一句话：**搜索结果是线索，不是证据；排名不是可信度排名。**

## 0. 通道定案

- **正式通道：直连 http://127.0.0.1:45678/rpc 的 web.search**（JSON-RPC tools/call；无需 MCP 会话；中文必须 UTF-8 字节体）
- helper：`scripts/websearch.ps1 -Query "关键词" -MaxResults 8`（返回 title/url/snippet）
- 弃用通道：`web_search`（需 DEEPSEEK_API_KEY，无官方 key）；simple MCP 的 web_search 工具（客户端会话陈旧，Session not found）
- 参考指南：`H:/ai_works/SimpleMcpServer/docs/SimpleMCPServer搜索指南.md`

## 1. 调用方式

- PowerShell：Invoke-RestMethod -Uri http://127.0.0.1:45678/rpc -Method Post -ContentType 'application/json; charset=utf-8' -Body $utf8bytes（先 ConvertTo-Json 再 Encoding.UTF8.GetBytes）
- provider 顺序：serper(Google)→google→bing→ddg-html→ddg-lite；首个返回非空者即返回（缺凭据/不可达自动跳过）；可用 webSearch.order 配置

## 2. 查询写法

- 三类：事实查询（主题+人物/日期/数字）、来源查询（+official/report/original/WHO/档案）、争议查询（+controversy/disputed/review）
- 中文人物：短查询定位线索，如 `祖己 高宗肜日`、`商容 表商容之闾 史记`；不要发一个超长中文问题

## 3. 核验纪律

1. **来源去重**：转载/同一来源链只算一个来源；十篇转载 ≠ 十个独立来源
2. **来源层级**：官方/原始 → 论文/档案/调查报告 → 专业机构/博物馆 → 高质量新闻/传记 → 百科/自媒体（第 4-5 层只能当线索）
3. **四项核对**：时间（事件 vs 发布日）、定义（概念是否同一口径）、范围（全球/国家/地区/机构）、因果（证明/支持/认为/推测）
4. **进入正文最低要求**（满足其一）：官方/原始来源直接支持；两份以上独立高质量来源一致；官方+学术交叉且口径一致；有争议但主流解释清楚（正文用保守限定词）
5. 以下**不可**写成确定事实：只有搜索摘要；单一公众号/自媒体；转载链；无年份/口径的数字；宣传性“第一/唯一/首创”；标题或推测式因果

## 4. 追原文

- 重要事实用 `web_fetch` 打开命中 URL 核验原文后再用；检索日期与来源 URL 进证据卡

## 5. 落地到《人物事迹.md》

- 每专辑 文案/人物事迹.md 的人物条目注明：本事（身份/功绩/美德 或 罪状）+ 史料来源（正史章句/档案/权威页 URL）+ 异说注（如 祖己=孝己 之辩）+ 检索批次日期
- 证据卡（来源对照表）随文件存档：`主张 | 各引擎命中 | 原始来源 | 最终处理（写实/保守/存疑）`
